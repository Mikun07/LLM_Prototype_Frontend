This version is an interface design change because the Run step now performs real backend
cancellation and the dashboard contract is updated for the latest backend report shape.

## Plain-Language Summary

Version `v2.9.0` improves how the frontend works with the backend during analysis. The
Cancel button now asks the backend to stop the active run, instead of only stopping the
browser polling loop. The dashboard can display the new `project` field on inconsistency
results. Runtime dependency audit issues were also cleaned up in the lockfile, and the
Configure step text now describes the Type column accurately.

## What Changed From v2.8.0

| Area | What changed | Why |
|---|---|---|
| API client | Added `cancelAnalysis(runId)` for `POST /api/cancel/{runId}` | Gives the UI a real backend cancellation path |
| Run hook | `cancelRun()` now calls the backend and handles `cancelled` polling responses | Prevents background backend work from continuing after the user cancels |
| Types | Added `cancelled` to `RunStatus` and `PipelineStatus` | Keeps TypeScript in sync with backend `v1.3.0` |
| Types | Added `project` to `InconsistencyResult` | Keeps dashboard and PDF data aligned with backend reports |
| Run step | Added cancelled status rendering in the pipeline icon/status UI | Gives users a clear cancelled state |
| Badges | Added visual handling for `cancelled` pipeline status | Avoids unknown status styling |
| Dashboard | Inconsistency tables include project data and searchable project text | Makes large reports easier to review |
| PDF utilities | Inconsistency report rows include project and domain context | Keeps exported reports easier to trace |
| Configure copy | Type-column wording no longer says routing is automatic | Removes a misleading explanation |
| Tests | Added API request coverage for backend cancellation | Protects the new client endpoint path |
| Dependencies | `package-lock.json` was refreshed with non-vulnerable runtime resolutions | Clears production dependency audit findings |

## Backend Assumption

This version expects ReqSmell Backend `v1.3.0` or later running at:

```text
http://localhost:8000
```

The backend must provide:

| Method | Path |
|---|---|
| `POST` | `/api/upload` |
| `POST` | `/api/analyse` |
| `GET` | `/api/status/{runId}` |
| `POST` | `/api/cancel/{runId}` |

## Upgrade Notes

Upgrading from `v2.8.0` to `v2.9.0`:

- Run `npm ci` so the updated lockfile dependencies are installed.
- Use backend `v1.3.0` or later for real cancellation support.
- Code that handles run or pipeline status must include `cancelled`.
- Code that handles inconsistency rows must include `project`.

## Downgrade Notes

Returning from `v2.9.0` to `v2.8.0`:

```powershell
npm run version:use -- -Version v2.8 -CleanIgnored -Install
```

- The Cancel button no longer stops backend work.
- `cancelled` is no longer part of the status unions.
- Inconsistency results no longer include the `project` field.
- Runtime dependency audit results return to the v2.8.0 lockfile state.
